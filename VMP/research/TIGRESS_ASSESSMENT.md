# Tigress VM 挑戰研究評估

Tigress VM 挑戰適合作為目前課題的跨虛擬化器實驗。它能用來檢查符號分析與還原流程面對不同分派、處理函式及多層虛擬化時的適用性；結果應獨立於 VMP 案例統計。本文保留啟動前的官方規則、生成腳本與公開分析實作評估；後續的實作與五個 VM-0 樣本結果見 [實驗報告](TIGRESS_REPORT.md)。

## 官方案例與驗收要求

官方列有七組挑戰，每組五個程式：

| 組別 | 保護組合摘要 |
|---|---|
| 0000，也稱 VM-0 | 單層 VM、隨機分派 |
| 0001 | 超級指令、拆分指令處理函式 |
| 0002 | 假函式、隱式資料流 |
| 0003 | 算術編碼、函式拆分及合併 |
| 0004 | 雙層 VM、隱式資料流 |
| 0005 | VM 與一層 JIT |
| 0006 | 雙層 JIT |

官方目標為恢復可讀且可由 gcc 編譯的 C，並保留迴圈及複合資料結構等特徵；完成一組需處理該組全部程式。只輸出展開的 LLVM IR 或對部分輸入相同，不能直接宣稱滿足這個標準。[官方挑戰說明與規則](https://tigress.cs.arizona.edu/challenges.html)

第 0000 組的生成腳本對 SECRET 做 Virtualize，使用 stack 運算元及由種子選擇的分派形式，適合作為第一個控制實驗。[官方生成腳本](https://tigress.cs.arizona.edu/scripts_txt/0000.sh.txt)

官方提供 [Linux x86-64 下載包](https://tigress.cs.arizona.edu/tigress-challenges-Linux-x86_64.zip)。本輪僅核對頁面上的下載連結，尚未測試壓縮包是否可成功取得。

## 公開研究實作的啟示

Salwan 的 Tigress 倉庫提供挑戰樣本、符號表達式、LLVM IR 及還原結果，可作為研究對照；這些是上游成果，不是本課題已重現的結果。README 的歷史流程提及 Arybo，但本輪讀到的 solve-vm.py 已直接使用 Triton 的 liftToLLVM，選用依賴時應以固定版本程式碼為準。[研究倉庫](https://github.com/JonathanSalwan/Tigress_protection)、[實際分析腳本](https://github.com/JonathanSalwan/Tigress_protection/blob/master/solve-vm.py)

該腳本包含 ELF 載入、重定位及函式攔截：在 strtoul 的結果建立符號輸入，在 printf 的輸出參數擷取符號表達式。它從程式入口模擬指令，與目前 VMP 案例的既有 trace 重播不同；原腳本的再編譯階段還呼叫外部 clang。因此，不能把 Tigress ELF 的路徑直接交給目前的 VMP 重播器。

## 本地條件與需要新增的能力

本輪檢查確認現有研究虛擬環境能匯入 Triton 與 llvmlite，尚無 LIEF。這只表示依賴條件，不能當作 Tigress 重現成功的證據。

| 可沿用 | 需新增或核對 |
|---|---|
| LLVM 最佳化及本機函式執行 | ELF 載入與重定位，或相應解析工具 |
| 形參名稱及位元寬度映射 | Linux 呼叫慣例與外部函式模型 |
| SMT、邊界值與反例記錄 | 實際指令模擬、停止條件及資源限制 |
| 每次執行的來源、日誌與產物保存 | 原始樣本的獨立對照執行環境 |
| 已有旗標建模經驗 | 自動路徑探索及多路徑涵蓋 |

Windows 上的 Triton 可作為指令語義引擎；完整 ELF 執行仍需正確的載入及環境模型。若要以原始 Linux 程式作獨立對照，需另有相容環境。不能把兩個共享相同錯誤模型的模擬器互相比對，當作獨立正確性驗證。

## 建議實驗次序與驗收

1. 固定上游 commit，取得 VM-0 的五個樣本及相關腳本，記錄雜湊、格式、入口點和外部依賴。
2. 先針對一個樣本完成實際指令模擬，從輸入來源追到輸出，記錄具體值與符號表達式。
3. 產生還原 IR，與原始樣本做相同輸入比對；保留邊界值、隨機值、路徑條件及失敗案例。
4. 在五個 VM-0 樣本上使用同一套流程，區分共用程式與個別人工配置。
5. 若要符合官方 source recovery 要求，另做迴圈與資料結構恢復，產生可讀的 C；與單純 LLVM 函式還原分開驗收。
6. 接著逐組加入 VM-1、VM-2、VM-3 及 VM-4。JIT 組另立實驗，處理執行時生成的程式碼與記憶體更新，不先承諾既有流程支援。

第一階段目標應定為「VM-0 五個樣本的函式語義還原與獨立執行比對」。之後再研究「還原高階 C 結構」，能清楚界定研究增量，避免將上游解法重跑等同於原創演算法成果。

## 對目前課題的意義

Tigress 能增加保護機制的多樣性，但不能替代 VMP 實驗。建議報告分成 VMP 已驗證成果、Tigress 新增成果及尚未支援特徵三部分，各自列出案例、假設與證據。本輪新增的是可行性評估，未新增已解案例數。
